## Fill each knowledge domain

| Document | Required source evidence or explicit unknown |
|---|---|
| PROJECT / STACK_MAP | Purpose, source roots, workspace/framework declarations vs observed versions, runtime boundaries and unresolved assumptions |
| ARCHITECTURE | Actual entrypoint/routing/DI/module/service/data/render path; diagram only when evidence supports it |
| MODULES | Owning directories, responsibilities and dependencies; distinguish duplicate names by full path |
| SOURCE_MAP | Task/question → exact owning files and read order, with source references/line locations when actually known |
| CONFIG | Environment selection/config precedence/shared paths; record key names/locations, never secret values |
| FLOWS | Important success/error/data paths traced through actual source, with rollback/external IO uncertainty visible |
| DATA_MODEL | Source-inferred entities/relations vs inspected schema; if no persistence exists give the source-backed reason for not_applicable |
| OPEN_QUESTIONS | Missing files, unknown semantics/versions, unavailable tools/runtime/docs and next concrete inspection |
| FINDINGS | Only supported observations, prerequisites/counterevidence/verification/remediation status; not an automatic security scan |
| GRAPHIFY | Actual graph provenance/health/freshness when available, otherwise pending/unavailable with a source-map fallback |
| TASKS / SESSION_LOG / DECISIONS | Real ownership/work/results/decisions, no invented historical activity or implicit permissions |
| COLLABORATION / HANDOFF_PROTOCOL / NEXT_AGENT_PROMPT | One-writer rules, stop/checkpoint/transfer, required read order and actual capability limits |
| VERIFICATION / SETUP / HANDOFF | What exists, what was checked, exact evidence, remaining unknowns and next action; separate document checks from application/runtime coverage |

An empty template, filename count or package match is not completed understanding. For every domain record current source evidence, a specific unknown with a next action, or a justified not_applicable. Trace actual important success/error paths before claiming behavior is understood. Complete edition means complete coverage of these knowledge domains, not proof that every source line/runtime/security path is verified.

Use local manifests/source/docs first; verify uncertain version-specific facts with official docs if network access is available. When unavailable keep the claim unknown. Do not run database/notification/API writes, deploy, install tooling or launch vulnerability scans just to fill a domain.

## Verify and hand off

Use available native tools for actual files/links/placeholders/source references, preservation, unsafe/missing-resource cases and relevant existing tests. Record exact actions/environment/results in the task packet and project VERIFICATION summary. App/browser checks not run remain not_run/unverified; graph work is optional, never fake.

Hashes not computed stay not_computed. Unused optional JSON gate is not_run_optional. Existing project-required schemas/gates still take precedence; do not silently downgrade them. Keep required checks that cannot run pending rather than presenting a fully verified completion.

Finish with a concise coverage report: known/source-backed, unknown/not_applicable, actually tested, not_run, remaining work and where the next agent begins. The handoff must stand alone without chat history; stop the previous writer before transfer. Native helpers are optional, and no Graphify output or universal agent compliance is claimed unless actually established.
